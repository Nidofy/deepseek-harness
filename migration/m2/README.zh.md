# 连接与旧数据

[English](README.md) | 中文

派生桌面保留官方 Host、Agent loop 和 Session writer。应用菜单中的 **连接与数据迁移** 可配置独立的 OpenAI Chat Completions 或 Anthropic Messages 连接，将旧数据导入独立目录，并启用指定文件保护。官方模型选择器以 `nidofy-<connection>` 显示已保存路由。官方 Settings → Models 仍可使用；不可变修订和恢复保证适用于此编辑器保存的连接。

## 连接

填写连接标识、端点、协议、模型 ID 和 API Key。可选的 `catalogProvider` 用于继承已安装目录。OpenAI 基地址通常以 `/v1` 结尾；Anthropic 基地址省略末尾的 `/v1`。独立连接可使用相同模型 ID 和不同凭据。编辑已有连接会保留高级模型声明和配置选项。每次保存需填写 Key；提交后清空密码框，不会将已存储 Key 读回界面。

每次保存都会生成不可变修订，并在官方凭据服务中建立新引用。活动请求及其重试保留已捕获的配置和 Key；新步骤采用当前修订。撤销会阻止保留中的租约再次发送请求，但不能撤回已发出的 HTTP 请求。Host 串行处理保存，拒绝过期的预期修订，并返回操作 ID、Host 代次、期望/生效修订及不含凭据的摘要。响应不确定时，重新读取可查询操作是否提交。恢复日志不含 Key。无引用修订仅在回退窗口结束且所有请求/重试租约释放后退休。进程终止测试覆盖准备、凭据暂存、提交和应用；不据此承诺断电后的文件系统持久性。

热修改共享 Host 已有网络传输。本编辑器不提供代理和 CA 替换；改变部署网络环境后需重启完整应用。Provider 库仅增加内置目录别名、请求局部 payload 准备及公开的配置/凭据组合辅助函数；对话转换和官方重试循环仍由原模块负责。

## 副本导入

退出旧应用，选择数据根目录及桌面版本后导入。导入器识别旧 `settings.yaml` 与 `profiles/dsh-desktop/cordis.patch.yml`，按当前加载的官方插件校验设置，并生成新的 `profiles/desktop` patch。存在歧义的设置、内联秘密、可执行插件声明、未知 Session 代次、不支持的工作区格式、链接文件和观察到的写锁均会被拒绝。官方 reader 先验证每份 Session 副本，再由官方迁移链写入后继代次。源文件保持不变；用相同操作 ID 重试中断的导入可继续处理或返回已有回执。

旧 registry 适配器为旧桌面基线声明 writer 代次 3，为源码候选声明代次 4。测试覆盖这两代、额外的历史代次 0、未来代次 999 拒绝及中断恢复。Session 压缩形式保持不变。附件和工作区记录随副本迁移，查询索引重建。已启用的文件保护范围保留到新 home，继续接受原生身份检查。已有自动化计划保留在源目录，导入不会激活计划。

回执提供独立的 `dataRoot`。启动完整桌面包前，将 `NIDOFY_DESKTOP_DATA_ROOT` 设置为该绝对目录；源目录继续作为回退副本。导入的连接建议会显示在编辑器中，用户绑定新 Key 前不具备活动凭据。设置中的凭据引用会替换为刻意不存在的新引用。旧网络、缓存与模型能力覆盖项保留在回执中待审阅，不会作为未经验证的设置启用。导入不合并当前运行的 home，也不启动第二个 Host。

## 文件保护

在同一编辑器中，为本地工作区的 1–128 个明确相对文件路径启用保护。随包 Rust helper 保留旧版 Win32 句柄、重解析点、硬链接、文件系统身份和 VCS 元数据检查。Host 在首个模型步骤前确认采集，并在每次官方工具分派前重新检查身份。原生操作缺失、过期或失败会阻断执行。采集或封存结果未知时，重启前阻止后续受保护任务进入，已有记录保留供检查。

子会话不能静默绕过准入。[工程工作台](../m3/README.zh.md) 协调运行时归属明确的子任务、不相交工作区及工程命令，并根据最新预览执行恢复。连接编辑器提供范围配置和快照检查。这些快照不会约束外部进程。

## 验收与跟随官方更新

官方 Windows 打包命令使用 Cargo 锁文件构建 helper，仅将其包含在派生 Windows 发行包中。构建所用 Node 必须位于打包会重建的 runtime 目录之外。应保留完整 `personal-unsigned/win-unpacked` 目录，单独可执行文件不构成应用。基线与先前发行证据仍见 [M0](../m0/source-lock.json) 和[个人版验收](../personal/README.zh.md)。

集中测试位于 Desktop Host 和 pi-ai adapter 旁。`check-process-loss.mjs` 会终止独立测试所有者并重新打开日志；`smoke-desktop.mjs` 使用私有数据、合成凭据和本地流式 provider 启动真实打包 Electron，覆盖认证路由、保存 B 时 A 重试、新 B 请求、独立凭据、原生保护、编辑器、重启及导入副本。[证据](evidence/summary.json)记录实际结果与测试包。真实 provider 凭据和企业现场验收独立于本地确定性验收。

跟随官方更新时，重放窄范围 pi-ai 增量及 Desktop 组合改动，重建完整包集，再重复连接、数据、保护及打包运行时检查。不得热换 Host 或单独替换运行时模块。Rust 源码记录见[原生来源](../../native/nidofy-protection/origin.json)。
